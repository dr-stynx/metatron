## architecture

image:nenofhat-alchemy-laboratory.png[width=500,float=left,role="parchment marker"] The fundamental architecture of [.metatron] is realized as a network of coupled https://en.wikipedia.org/wiki/Ring_(mathematics)[algebraic rings] executing all levels of abstraction -- from the human-readable/writeable programming language, to the compiler that generates a sequence of instructions for the virtual machine to evaluate using a swarm of atomic monadic processors that ultimately read and write data identified by a ring-based id system supported by a heterogeneous set of data stores called __spaces__.
Each of these components follows the axioms of an algebraic ring (or some subset algebra such as a monoid or group).

### algebraic ring theory

A ring is a set of elements latexmath:[R] along with two binary operators

[stem]
++++
+\colon R \times R \rightarrow R
++++

and

[stem]
++++
*\colon R \times R \rightarrow R,
++++

where latexmath:[*] distributes over latexmath:[+] such that for latexmath:[a,b,c \in R],

[latexmath]
++++
\begin{align*}
a*(b+c) =\;& (a * b) + (a * c) \\
        =\;& (ab)    + (ac) \\
        =\;& ab      + ac.
\end{align*}
++++

Likewise,

[latexmath]
++++
\begin{align*}
(b+c)*a =\;& (b * a) + (c * a) \\
        =\;& (ba)    + (ca) \\
        =\;& ba      + ca.
\end{align*}
++++

A useful corollary of the distributive nature of latexmath:[+] provides an equivalency for polynomial rings, whereby

[latexmath]
++++
\begin{align*}
(a+b)*(c+d) =\;& ((a+b)*c) + ((a+b)*d) \\
            =\;& (ac+bc) + (ad+bd) \\
            =\;& ac+bc+ad+bd.
\end{align*}
++++

Every ring latexmath:[R] contains two unique elements latexmath:[0 \in R] and latexmath:[1 \in R] such that, for every latexmath:[a \in R],

[latexmath]
++++
\begin{align*}
0 + a &= a & a + 0 &= a \\
0 * a &= 0 & a * 0 &= 0 \\
1 * a &= a & a * 1 &= a.
\end{align*}
++++

Finally, every element latexmath:[a \in R] has an _inverse_ latexmath:[\text{-}a \in R], where

[latexmath]
++++
\begin{align*}
0 =\;& a + (\text{-}a) \\
  =\;& a - a,
\end{align*}
++++

and no two elements share the same inverse: latexmath:[\forall a,b \in R: \text{-} a \neq \text{-} b].

These are the axioms of ring theory.
The entire structure of a ring is denoted

[stem]
++++
\left(R,+,-,0,1\right),
++++

where each symbol is replaced by the corresponding operator and elements of the respective ring being defined.
Any collection of tokens, processes, objects, identifiers, etc. that obey these rules form, by definition, a ring and can be manipulated by the stated equivalencies and their formal derivatives.

## Core Concepts

[metatron] has a few core concepts that interact with each other in interesting ways. It is important that these concepts are understood completely if one wishes to become effective with the language. 


### fURIs

The first concept to understand is the definition and purpose of a fURI -- a "fhat" Uniform Resource Identifier. `fURIs` are used to denote the type, extension, and location of an `obj` (object) in metatron. fURIs are so important that they compose 2 of the 3 components defining an `obj`. An `obj` is defined as:

++++
\begin{align*}
\texttt{obj} \in \left(\texttt{tid} \times \texttt{jvm} \times \texttt{vid}\right),
\end{align*}
++++

where  `tid` is a _type_ (class) `fURI`, `jvm` is an object of the Java virtual machine, and `vid` is a _value_ (instance) `fURI`. In other words, an `obj` in metatron is accompanied by the specification of its structure (`tid`), its data structure (`jvm`), and an explicit reference to its location in memory (`vid`). This abstract triple is used by every type of obj, from monos (primitives), to polys (containers), and insts (functions).

Every fURI is composed of the following components:

. *scheme*: the protocol or namespace of the fURI
. *authority*: the host or domain of the fURI
. *path*: the path or resource of the fURI
. *coefficient*: the multiplicative factor of the fURI (called a `c`)
. *query*: the query parameters of the fURI (called a `q`)

The first 3 components above are familiar to most as they form the reference architecture of the world wide web (the https://en.wikipedia.org/wiki/Uniform_Resource_Identifier[ Uniform Resource Identifier] or URI). These aspects make it possible for `objs` to reference each other across memory, across machines, and across networks. The last 2 components are unique and have a special role to play in the meta structures and processes surrounding an `obj`.

#### Coefficient

A coefficient denotes the number of `objs` referred to by the specified fURI. In general, a coefficient is defined by the pair:

++++
\begin{align*}
\texttt{c} \in \left(\mathbb{N} \times \mathbb{N}\right),
\end{align*}
++++
where the left component is the minimum number of `objs` referred to by the fURI and the right component is the maximum number of `objs` referred to by the fURI. The instance `objs` below demonstrate the compressing power of coefficients. Instead of denoting 3 identical `1`-`objs`, a single `1` valued `obj` with a coefficient of `{3}` can be used. This compression is not only useful as a shorthand when writing expressions, but also within the metatron virtual machine where the number of computations performed can be reduced significantly (e.g. from stem:[\mathcal{O}(n) \text{ to } \mathcal{O}(1)]).

#### Merge and Split Operators

The **merge operator** (`>-`) and **split operator** (`-<`) are fundamental to understanding how coefficients interact in stream processing.

**Merge Operator (`>-`)**: Merges branches into a single stream

When branches are merged, objects with the same value have their coefficients summed (the **bulk axiom**):

++++
<!-- 🐖
{1,2,3}                      [-- <1>
{1,2,3}-<[+1,+2,+3]          [-- <2>
{1,2,3}-<[+1,+2,+3]>-        [-- <3>
-->
++++
<1> Set displays as 3 separate branches
<2> Split each element into operations (creates nested branches)
<3> Merge back: duplicate values get quantified (e.g., `int{2}::3` means 3 appears twice)

**Split Operator (`-<`)**: Splits a stream into branches

The split operator is the opposite of merge, creating parallel branches from a single stream:

++++
<!-- 🐖
10-<[?<10 => 'less than 10', ?>=9 => 'greater than 9']    [-- <1>
10-<[?<10 => 'less than 10', ?>=9 => 'greater than 9']>>  [-- <2>
-->
++++
<1> Split into conditional branches, returns matching branch
<2> Using `>>` extracts the range (value) from the relation

#### Quantifier Interference

Coefficients can be **negative**, enabling constructive and destructive interference when branches are merged:

++++
<!-- 🐖
[1,2,3]                              [-- <1>
[1,2,3]+[int{-1}::1]                 [-- <2>
[1,2,3]+[int{-1}::1]>-               [-- <3>
[1,int{100}::2,3]+[int{-75}::2]>-    [-- <4>
-->
++++
<1> List with three elements
<2> Add element 1 with coefficient -1 (not yet merged)
<3> **Destructive interference**: 1 + (-1) = 0, so element 1 disappears
<4> **Partial interference**: 100 + (-75) = 25, resulting in `int{25}::2`

**Key Principle**: When merging, coefficients of identical objects are summed. If the sum equals zero, the object disappears (annihilation).

#### Quantifier Pattern Matching

Coefficients support regex-style range patterns for matching:

++++
<!-- 🐖
[int{25}::3].matches([int{25}::T])   [-- <1>
[int{25}::3].matches([int{24}::T])   [-- <2>
[int{25}::3].matches([int{10,30}::T]) [-- <3>
[int{25}::3].matches([int{10,}::T])  [-- <4>
[int{25}::3].matches([int{*}::T])    [-- <5>
[int{25}::3].matches([int{+}::T])    [-- <6>
[int{25}::3].matches([int{?}::T])    [-- <7>
-->
++++
<1> Exact match: coefficient must be exactly 25
<2> Exact match fails (24 ≠ 25)
<3> Range match: coefficient between 10 and 30
<4> Open-ended range: coefficient >= 10
<5> Wildcard: any coefficient (0 or more)
<6> One or more: coefficient >= 1
<7> Zero or one: coefficient 0 or 1 (fails for 25)

#### Query

Metatron supports powerful query capabilities through pattern matching and filtering.
Queries can be expressed using filter functions, pattern matching with wildcards, and conditional branching.

**Basic Query Pattern:**
```mtron

```

**Pattern Matching:**
```mtron

```

**Conditional Queries:**
```mtron

```

See the instruction set documentation for detailed query operations.

== programming idioms

=== data types

Every `obj` has the form:

++++
\begin{align*}
\texttt{obj} = \left(\texttt{uri} \times X \times \texttt{uri} \right),
\end{align*}
++++

where the first `uri` is the `tid` (_type identifier_), the last `uri` is the `vid` (_value identifier_), and the middle `X` denotes the data type of the `obj` within the constructs of the underlying programming language's implementation.
On the Java virtual machine, `X` is a `java.lang.Object`, where, for instance, the `X` of `/m/int` is `java.lang.Long`.

The referent of an `obj's` `tid` is a `type` `obj` of the form

++++
\begin{align*}
\texttt{type} = \left(\texttt{uri} \times \underbrace{\left(\texttt{code} \times \texttt{code}\right)}_{X} \times \texttt{uri} \right),
\end{align*}
++++

where the `code` pair is composed of the type's

1. **predicate**: `code` to determine if the `obj` meets the criteria of being the respective `type`, and
2. **constructor**: `code` to generate an instance of the `type`.

Finally, of particular import, for a type, it is always the case that latexmath:[\forall t \in T : t_\texttt{tid} = t_\texttt{vid}].
The significance of this equality will be made salient later in the documentation.

To practically ground these concepts, a https://en.wikipedia.org/wiki/Natural_number[natural number] type is defined.

++++
<!--
┌ ├ ┐ └ ┘ │ ┤ ─ ⋰ ⋱ ⮝ ⮞ ⮜ ⮟
-->
++++

[source,mtron,role="center"]
----
          nat::T[?>0][-<|[?<0 => ⋅-1,_ => _]>>] 
          │    │ │    │
          │    │ │    └──────────── constructor
          │    │ └───────────────── predicate
          │    └─────────────────── type symbol
          └──────────────────────── tid
----

A quick explanation of the type predicate and constructor `code` is as follows:

1. **predicate** [`?>0`]: is (`?`) greater than (`>`) 0.
2. **constructor** [`-<|[?<0 \=> ⋅-1,_ \=> \_]>>`]: if (`-<|`) less than (`<`) 0, then (`\=>`) multiply (`⋅`) by -1, else do (`\=>`) nothing (`_`).
Yield the _range_ (`>>`) of the relation constructed (the specifics of `>>` will be discussed later).

Example usage of the defined `nat` type is presented below.

++++
<!-- 🐖
nat -> int::T[?>0][-<|[is(lt(0)) => ⋅-1,_ => _]>>]    [-- <1>
*nat                                                  [-- <2>
nat::2                                                [-- <3>
nat::-2                                               [-- <4>
2.as(nat::T)                                          [-- <5>
-2.as(nat::T)                                         [-- <6>
nat::2 ⋅ -1                                           [-- <7>
-->
++++

<1> A natural number (`nat`) is a positive `int`.
The predicate component of the type definition tests an `int` to determine if it's a `nat` and the constructor component will generate a positive `int` given any `int` (i.e. the absolute value).
<2> the `nat` _tid_ references the respective `nat` type `obj`.
<2> 2 is an `nat`.
<3> -2 is not a `nat`, but given the constructor, becomes a `nat`.

While every `type` is an `obj`, not every `obj` is a `type`.
Those `objs` that are not `types` are _instances_ of some `type`.
This is the foundation for all other `objs` in [metatron].

==== poly types

Poly types are **branched structures** where each element or entry represents a separate branch.
The two primary poly types are:

**lst (List)** - Ordered collection where each element is a branch:

++++
<!-- 🐖
[a,b,c]                     [-- <1>
[1,2,3]                     [-- <2>
[,]                         [-- <3>
-->
++++
<1> List with three branches: a, b, and c
<2> List with three integer branches
<3> Empty list (no branches)

**rec (Record)** - Key-value pairs where each entry is a branch:

++++
<!-- 🐖
[a=>1,b=>2,c=>3]            [-- <1>
[name=>'Alice',age=>30]     [-- <2>
[=>]                        [-- <3>
-->
++++
<1> Record with three branches: a=>1, b=>2, and c=>3
<2> Record representing a person
<3> Empty record (no branches)

**Key Characteristics:**

* Each element/entry is a separate branch
* `.count()` returns 1 (the poly object itself)
* `>-.count()` merges branches and counts elements/entries
* Branches can be processed in parallel
* Support pattern matching and wildcards

**Branching in Action:**

++++
<!-- 🐖
[1,2,3]                     [-- <1>
[1,2,3].count()             [-- <2>
[1,2,3]>-.count()           [-- <3>
[a=>1,b=>2].count()         [-- <4>
[a=>1,b=>2]>-.count()       [-- <5>
-->
++++
<1> List with 3 branches
<2> Returns 1 (the list object itself)
<3> Returns 3 (merges branches, counts elements)
<4> Returns 1 (the record object itself)
<5> Returns 2 (merges branches, counts entries)

**Operations on Poly Types:**

++++
<!-- 🐖
[1,2,3].reverse()           [-- <1>
[1,2,3].plus([4,5])         [-- <2>
[1,2,3].merge()             [-- <3>
[a=>1,b=>2].dom()           [-- <4>
[a=>1,b=>2].rng()           [-- <5>
[a=>1,b=>2,c=>3].select([a=>_,b=>_])  [-- <6>
-->
++++
<1> Reverse list order
<2> Concatenate lists
<3> Merge list into a set
<4> Get domain (keys) of record
<5> Get range (values) of record
<6> Select specific keys from record

=== instructions

An `inst` is an `obj` of the form:

++++
\begin{align*}
\texttt{inst} = \left(\texttt{uri} \times \left( \texttt{poly} \times \texttt{code} \right) \times \texttt{uri} \right),
\end{align*}
++++

where each component is:

1. `uri`: the `inst` type (e.g. `/m/inst/plus`).
2. `poly`: the `inst` arguments which can either be a `lst` or a `rec`.
3. `code`: the `code` that defines the behavior or function of the `inst`.
4. `uri`: the `inst` location in space.

pattern -> [a=>_,b=>_]                                    [-- <1>
data -> [a=>1,b=>2,c=>3,d=>4]                             [-- <2>
*data.select(*pattern)                                    [-- <3>
-->
++++
<1> Define pattern as variable
<2> Define data as variable
<3> Use both variables in operation

=== conditionals

Conditionals in Metatron use the split operator (`-<`) to create branches based on predicates.
Each branch is evaluated independently, and matching branches are returned.

**Basic Conditional:**

++++
<!-- 🐖
5-<[?<10 => 'small', ?>=10 => 'large']                    [-- <1>
15-<[?<10 => 'small', ?>=10 => 'large']                   [-- <2>
-->
++++
<1> 5 is less than 10, returns 'small'
<2> 15 is greater than or equal to 10, returns 'large'

**Multiple Conditions:**

++++
<!-- 🐖
7-<[?<5 => 'tiny', ?<10 => 'small', ?<20 => 'medium', _ => 'large']    [-- <1>
25-<[?<5 => 'tiny', ?<10 => 'small', ?<20 => 'medium', _ => 'large']   [-- <2>
-->
++++
<1> First matching condition: 7 < 10, returns 'small'
<2> No condition matches, wildcard `_` returns 'large'

**Conditional with Computation:**

++++
<!-- 🐖
-5-<[?<0 => ⋅-1, _ => _]                                  [-- <1>
10-<[?<0 => ⋅-1, _ => _]                                  [-- <2>
-->
++++
<1> Negative number: multiply by -1 to get absolute value
<2> Positive number: return as-is

**Extracting Values with `>>`:**

++++
<!-- 🐖
10-<[?<10 => 'less', ?>=10 => 'greater or equal']         [-- <1>
10-<[?<10 => 'less', ?>=10 => 'greater or equal']>>       [-- <2>
-->
++++
<1> Returns relation: `[10=>'greater or equal']`
<2> Using `>>` extracts the range (value): `'greater or equal'`

**Advanced: Nested Conditionals:**

++++
<!-- 🐖
15-<[?<10 => 'single digit', _ => _]-<[?<20 => 'teens', _ => 'twenty+']>>    [-- <1>
-->
++++
<1> First condition fails, passes through, second condition matches

**Conditional Branching with Collections:**

++++
<!-- 🐖
{-2,-1,0,1,2}-<[?<0 => 'negative', ?eq(0) => 'zero', _ => 'positive']>>      [-- <1>
-->
++++
<1> Each element evaluated independently, returns multiple results

=== pattern matching

Pattern matching in Metatron allows you to match complex structures using wildcards, predicates, and structural patterns.

**Wildcard Matching (`_`):**

The underscore `_` matches any value:

++++
<!-- 🐖
[a=>1,b=>2,c=>3].select([a=>_])                           [-- <1>
[a=>1,b=>2,c=>3].select([a=>_,c=>_])                      [-- <2>
[a=>1,b=>2,c=>3].select([d=>_])                           [-- <3>
-->
++++
<1> Select entry with key 'a', any value
<2> Select entries with keys 'a' and 'c'
<3> No key 'd' exists, returns noobj

**Predicate Matching:**

++++
<!-- 🐖
[a=>5,b=>10,c=>15].select([_=>?>8])                       [-- <1>
[a=>5,b=>10,c=>15].select([_=>?<12])                      [-- <2>
-->
++++
<1> Select entries where value > 8
<2> Select entries where value < 12

**List Pattern Matching:**

++++
<!-- 🐖
[1,2,3].matches([_,_,_])                                  [-- <1>
[1,2,3].matches([_,_])                                    [-- <2>
[a,b,c].matches([a,_,_])                                  [-- <3>
-->
++++
<1> Matches: list has exactly 3 elements
<2> Doesn't match: list has 3 elements, not 2
<3> Matches: first element is 'a', rest can be anything

**Nested Structure Matching:**

++++
<!-- 🐖
x ->[a=>[b=>[1,2],c=>[3,4],f=>[5]]]                       [-- <1>
*x==[_=>[_=>[_,_]]]                                       [-- <2>
*x==[_=>[_=>==?[_,_]]]                                    [-- <3>
*x==[_=>[_=>==?[_,?>3]]]                                  [-- <4>
*x==[_=>[z=>==?[_,?>3]]]                                  [-- <5>
*x==[z=>[_=>==?[_,?>3]]]                                  [-- <6>
-->
++++
<1> Create nested record structure
<2> Match any record containing records with 2-element lists
<3> Match with equality check on 2-element lists
<4> Match lists where second element > 3
<5> Match inner key 'z' with predicate (no match)
<6> Match outer key 'z' with predicate (no match)

**Advanced: Quantifier Pattern Matching:**

++++
<!-- 🐖
[int{5}::1,int{10}::2,int{3}::3].select([int{+}::_])      [-- <1>
[int{5}::1,int{10}::2,int{3}::3].select([int{5,}::_])     [-- <2>
[int{5}::1,int{10}::2,int{3}::3].select([int{?}::_])      [-- <3>
-->
++++
<1> Select elements with quantifier >= 1 (all match)
<2> Select elements with quantifier >= 5
<3> Select elements with quantifier 0 or 1 (none match)

**Complex Pattern with Multiple Wildcards:**

++++
<!-- 🐖
[a=>[x=>1,y=>2],b=>[x=>3,y=>4]].select([_=>[x=>_]])       [-- <1>
[a=>[x=>1,y=>2],b=>[x=>3,y=>4]].select([_=>[y=>?>3]])     [-- <2>
-->
++++
<1> Select all entries containing nested 'x' key
<2> Select entries where nested 'y' value > 3

**Chaining Operations:**

<!-- 🐖

<1> Merge and add 1 to each (respecting quantifiers)

<3> Complete annihilation: 100 + (-50) + (-50) = 0, element disappears

++++
<1> Split: multiply small numbers by 10, large by 100, then merge
<2> Split: make negatives positive, keep others, then merge

**Nested Record Operations:**

<!-- 🐖
[a=>[x=>1,y=>2],b=>[x=>3,y=>4]].reverse()==[_=>reverse()]  [-- <1>
[a=>[x=>1],b=>[x=>2],c=>[x=>3]].select([_=>[x=>?>1]])      [-- <2>
-->
++++
<1> Reverse outer record and apply reverse to each inner record
<2> Select entries where nested x value > 1

<1> Classify numbers, merge results into set

=== barriers

Barriers are synchronization points in distributed computation where execution waits for multiple parallel branches to complete before proceeding.

**Purpose:**

* Synchronize parallel computations
* Ensure all branches complete before merging results
* Coordinate distributed operations across multiple machines

**Barrier Semantics:**

When branches are created via the split operator (`-<`), they execute in parallel.
A barrier ensures all branches complete before the next operation:

```mtron
{1,2,3}-<[operation1, operation2, operation3]  % Parallel execution
```

The merge operator (`>-`) acts as an implicit barrier, waiting for all branches to complete before merging results.

**Distributed Barriers:**

In distributed environments, barriers coordinate across network boundaries:

* Wait for remote computations to complete
* Synchronize state across multiple machines
* Ensure consistency in distributed transactions
