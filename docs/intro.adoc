1. a multi-model [.red]*database query language*

## architecture

image:nenofhat-alchemy-laboratory.png[width=500,float=left,role="parchment marker"] The fundamental architecture of [.metatron] is realized as a network of coupled https://en.wikipedia.org/wiki/Ring_(mathematics)[algebraic rings] executing all levels of abstraction -- from the human-readable/writeable programming language, to the compiler that generates a sequence of instructions for the virtual machine to evaluate using a swarm of atomic monadic processors that ultimately read and write data identified by a ring-based id system supported by a heterogeneous set of data stores called __spaces__.
Each of these components follows the axioms of an algebraic ring (or some subset algebra such as a monoid or group).

### algebraic ring theory

A ring is a set of elements latexmath:[R] along with two binary operators

[stem]
++++
+\colon R \times R \rightarrow R
++++

and

[stem]
++++
*\colon R \times R \rightarrow R,
++++

where latexmath:[*] distributes over latexmath:[+] such that for latexmath:[a,b,c \in R],

[latexmath]
++++
\begin{align*}
a*(b+c) =\;& (a * b) + (a * c) \\
        =\;& (ab)    + (ac) \\
        =\;& ab      + ac.
\end{align*}
++++

Likewise,

[latexmath]
++++
\begin{align*}
(b+c)*a =\;& (b * a) + (c * a) \\
        =\;& (ba)    + (ca) \\
        =\;& ba      + ca.
\end{align*}
++++

A useful corollary of the distributive nature of latexmath:[+] provides an equivalency for polynomial rings, whereby

[latexmath]
++++
\begin{align*}
(a+b)*(c+d) =\;& ((a+b)*c) + ((a+b)*d) \\
            =\;& (ac+bc) + (ad+bd) \\
            =\;& ac+bc+ad+bd.
\end{align*}
++++

Every ring latexmath:[R] contains two unique elements latexmath:[0 \in R] and latexmath:[1 \in R] such that, for every latexmath:[a \in R],

[latexmath]
++++
\begin{align*}
0 + a &= a & a + 0 &= a \\
0 * a &= 0 & a * 0 &= 0 \\
1 * a &= a & a * 1 &= a.
\end{align*}
++++

Finally, every element latexmath:[a \in R] has an _inverse_ latexmath:[\text{-}a \in R], where

[latexmath]
++++
\begin{align*}
0 =\;& a + (\text{-}a) \\
  =\;& a - a,
\end{align*}
++++

and no two elements share the same inverse: latexmath:[\forall a,b \in R: \text{-} a \neq \text{-} b].

These are the axioms of ring theory.
The entire structure of a ring is denoted

[stem]
++++
\left(R,+,-,0,1\right),
++++

where each symbol is replaced by the corresponding operator and elements of the respective ring being defined.
Any collection of tokens, processes, objects, identifiers, etc. that obey these rules form, by definition, a ring and can be manipulated by the stated equivalencies and their formal derivatives.

## Core Concepts

There are few concepts to understand, but in order to be effective, it is important that these concepts are understood completely. The first concept to learn is the definition and purpose of a fURI -- a "fhat" Uniform Resource Identifier. `fURIs` are used to denote the type, extension, and location of an `obj` (object) in metatron. fURIs are so important that they compose 2 of the 3 components defining an `obj`. An `obj` is defined as:

++++
\begin{align*}
\texttt{obj} \in \left(\texttt{tid} \times \texttt{jvm} \times \texttt{vid}\right),
\end{align*}
++++

where  `tid` is a _type_ (class) `fURI`, `jvm` is an object of the Java virtual machine, and `vid` is a _value_ (instance) `fURI`. In other words, every `obj` in metatron has a specification of its structure (`tid`), a structure (`jvm`), a reference to its explicit location in memory (`vid`).

Every fURI is composed of the following components:

. *scheme*: the protocol or namespace of the fURI
. *authority*: the host or domain of the fURI
. *path*: the path or resource of the fURI
. *coefficient*: the multiplicative factor of the fURI (called a `c`)
. *query*: the query parameters of the fURI (called a `q`)

The first 3 components above are familiar to most as they form the reference architecture of the world wide web. These aspects make it possible for `objs` to reference each other across memory, across machines, and across networks. The last 2 components are unique and have a special role to play in the meta structures and processes around an `obj`. For instance, a coefficient determines how many `objs` are denoted by the specified fURI. The `objs` below demonstrate the compressing use of an `obj's` coefficient.

++++
<!-- 🐖
{1,1,1}
{1,2,3}
{1,2,3}.type()
{1,2,3}.tid()
1-<[_,_,_]
1-<[_,_,_]>-
1-<{_,_,_}
-->
++++

The coefficient plays a more significant role with types. A coefficient, in general, is defined by the pair:

++++
\begin{align*}
\texttt{c} \in \left(\mathbb{N} \times \mathbb{N}\right),
\end{align*}
++++
where the left component is the minimum number of `objs` referred to by the fURI and the right component is the maximum number of `objs` referred to by the fURI. A salient example of coefficient ranges is demonstrated using types. Before proceeding with the example, its important to note that coefficients have a syntactic sugar form in metatron that borrows directly for the cardinality specifications in common regular expression languages.

.coefficient sugar notation

== programming idioms

=== data types

Every `obj` has the form:

++++
\begin{align*}
\texttt{obj} = \left(\texttt{uri} \times X \times \texttt{uri} \right),
\end{align*}
++++

where the first `uri` is the `tid` (_type identifier_), the last `uri` is the `vid` (_value identifier_), and the middle `X` denotes the data type of the `obj` within the constructs of the underlying programming language's implementation.
On the Java virtual machine, `X` is a `java.lang.Object`, where, for instance, the `X` of `/m/int` is `java.lang.Long`.

The referent of an `obj's` `tid` is a `type` `obj` of the form

++++
\begin{align*}
\texttt{type} = \left(\texttt{uri} \times \underbrace{\left(\texttt{code} \times \texttt{code}\right)}_{X} \times \texttt{uri} \right),
\end{align*}
++++

where the `code` pair is composed of the type's

1. **predicate**: `code` to determine if the `obj` meets the criteria of being the respective `type`, and
2. **constructor**: `code` to generate an instance of the `type`.

Finally, of particular import, for a type, it is always the case that latexmath:[\forall t \in T : t_\texttt{tid} = t_\texttt{vid}].
The significance of this equality will be made salient later in the documentation.

To practically ground these concepts, a https://en.wikipedia.org/wiki/Natural_number[natural number] type is defined.

++++
<!--
┌ ├ ┐ └ ┘ │ ┤ ─ ⋰ ⋱ ⮝ ⮞ ⮜ ⮟
-->
++++

[source,mtron,role="center"]
----
          nat::T[?>0][-<|[?<0 => ⋅-1,_ => _]>>] 
          │    │ │    │
          │    │ │    └──────────── constructor
          │    │ └───────────────── predicate
          │    └─────────────────── type symbol
          └──────────────────────── tid
----

A quick explaination of the type predicate and constructor `code` is as follows:

1. **predicate** [`?>0`]: is (`?`) greater than (`>`) 0.
2. **constructor** [`-<|[?<0 \=> ⋅-1,_ \=> \_]>>`]: if (`-<|`) less than (`<`) 0, then (`\=>`) multiply (`⋅`) by -1, else do (`\=>`) nothing (`_`).
Yield the _range_ (`>>`) of the relation constructed (the specifics of `>>` will be discussed later).

Example usage of the defined `nat` type is presented below.

++++
<!-- 🐖
nat -> int::T[?>0][-<|[?<0 => ⋅-1,_ => _]>>]          [-- <1>
*nat                                                  [-- <2>
nat::2                                                [-- <3>
nat::-2                                               [-- <4>
2.as(nat::T)                                          [-- <5>
-2.as(nat::T)                                         [-- <6>
nat::2 ⋅ -1                                           [-- <7>
-->
++++

<1> A natural number (`nat`) is a positive `int`.
The predicate component of the type definition tests an `int` to determine if it's a `nat` and the constructor component will generate a positive `int` given any `int` (i.e. the absolute value).
<2> the `nat` _tid_ references the respective `nat` type `obj`.
<2> 2 is an `nat`.
<3> -2 is not a `nat`, but given the constructor, becomes a `nat`.

While every `type` is an `obj`, not every `obj` is a `type`.
Those `objs` that are not `types` are _instances_ of some `type`.
This is the foundation for all other `objs` in [metatron].

=== instructions

An `inst` is an `obj` of the form:

++++
\begin{align*}
\texttt{inst} = \left(\texttt{uri} \times \left( \texttt{poly} \times \texttt{code} \right) \times \texttt{uri} \right),
\end{align*}
++++

where each component is:

1. `uri`: the `inst` type (e.g. `/m/inst/plus`).
2. `poly`: the `inst` arguments which can either be a `lst` or a `rec`.
3. `code`: the `code` that defines the behavior or function of the `inst`.
4. `uri`: the `inst` location in space.
