[.metatron] can be understood as

1. a multi-model [.red]*database query language*
2. a data-oriented [.red]*operating system*.

image:m-arch.svg[width=500,float=right] These representations are made salient by a ring-oriented programming language and virtual machine. As an example, within the metatron, an mtron-trained large language model is prompted to generate a multi-model expression to search multiple database (e.g. key/value, vector, graph), to then insert those results into a multiple web documents stored on multiple machines in a jQuery-esque manner, whereby a dynamically spawned web server then provides a single point of access to fetching the distributed documents to yield a single view via a browser.

## metatron architecture

image:nenofhat-alchemy-laboratory.png[width=500,float=left,role="parchment"] The fundamental architecture of [.metatron] is realized as a network of coupled https://en.wikipedia.org/wiki/Ring_(mathematics)[algebraic rings] executing all levels of abstraction -- from the human-readable/writeable programming language, to the compiler that generates a sequence of instructions for the virtual machine to evaluate using a swarm of atomic monadic processors that ultimately read and write data identified by a ring-based id system supported by a heterogeneous set of data stores called __spaces__. Each of these components follows the axioms of an algebraic ring (or some subset algebra such as a monoid or group).

### algebraic ring theory

A ring is a set of elements latexmath:[R] along with two binary operators

[stem]
++++
+\colon R \times R \rightarrow R
++++
and
[stem]
++++
*\colon R \times R \rightarrow R,
++++
where latexmath:[*] distributes over latexmath:[+] such that for latexmath:[a,b,c \in R],
[latexmath]
++++
\begin{align*}
a*(b+c) =\;& (a * b) + (a * c) \\
        =\;& (ab)    + (ac) \\
        =\;& ab      + ac.
\end{align*}
++++
Likewise,
[latexmath]
++++
\begin{align*}
(b+c)*a =\;& (b * a) + (c * a) \\
        =\;& (ba)    + (ca) \\
        =\;& ba      + ca.
\end{align*}
++++
A useful corollary of the distributive nature of latexmath:[+] provides an equivalency for polynomial rings, whereby
[latexmath]
++++
\begin{align*}
(a+b)*(c+d) =\;& ((a+b)*c) + ((a+b)*d) \\
            =\;& (ac+bc) + (ad+bd) \\
            =\;& ac+bc+ad+bd.
\end{align*}
++++
Every ring latexmath:[R] contains two unique elements latexmath:[0 \in R] and latexmath:[1 \in R] such that, for every latexmath:[a \in R],
[latexmath]
++++
\begin{align*}
0 + a &= a & a + 0 &= a \\
0 * a &= 0 & a * 0 &= 0 \\
1 * a &= a & a * 1 &= a.
\end{align*}
++++
Finally, every element latexmath:[a \in R] has an _inverse_ latexmath:[\text{-}a \in R], where
[latexmath]
++++
\begin{align*}
0 =\;& a + (\text{-}a) \\
  =\;& a - a,
\end{align*}
++++
and no two elements share the same inverse: latexmath:[\forall a,b \in R: \text{-} a \neq \text{-} b].

These are the axioms of ring theory. The entire structure of a ring is denoted
[stem]
++++
\left(R,+,-,0,1\right),
++++
where each symbol is replaced by the corresponding operator and elements of the respective ring being defined. Any collection of tokens, processes, objects, identifiers, etc. that obey these rules form, by definition, a ring and can be manipulated by the stated equivalencies and their formal derivatives.

### the rings of metatron

There are many rings in metatron. Of particular importance is the ring fURI -- a "fhat" Uniform Resource Identifier. `fURIs` are used to denote the type, extension, and location of an `obj` (object) in metatron. In fact, an `obj` in metatron is composed of three elements, one data structure and 2 `fURIs`, where:
++++
\begin{align*}
\texttt{obj} \in \left(\texttt{jvm} \times \texttt{tid} \times \texttt{vid}\right),
\end{align*}
++++
where `jvm` is an object of the Java virtual machine, `tid` is a _type_ (class) `fURI` and `vid` is a _value_ (instance) `fURI`. Every `obj` in metatron has a form, a denotation of that form, and a reference to its explicit location in _space_.
