    Interconnect Heterogeneous Data Sources and Processes

    metatron offers a concise, expressive, and efficient way to define and manipulate data structures encoded within and between data sources. It is designed to be used across a wide range of applications, from the enthusiast's home automation project to an organization's large-scale master data management system.

    metatron is founded on a referential record-oriented data model and schema. Higher-order structures are captured across a cluster of relational databases, graph databases, web servers, JSON documents, MQTT brokers, AI memory, IoT microprocessors, file systems, and more.

    Features

    mtron is a functional, type-safe, data flow language capable of expressing complex data transformations within a multi-model data environment

    mtron (pronounced /ɛm.trɒn/) is the primary query and transformation language for the metatron virtual machine. It provides a type-safe environment for processing data across a diverse set of spaces.

    In mtron, URIs and instructions are both first class citizens. The URI's structure is capitalized on throughout the language where, for example, query parameters encode instruction domain and range types. This leads to URIs referencing code composed of URIs which provides a unique level of software reflection without abandoning a functional structure.

    metatron objs exist in a single, unified uri address space where processes can seamlessly traverse across different data sources

    The fURI (functional URI) is the cornerstone of metatron's memory model. Every piece of data, regardless of its underlying storage, is addressed via a consistent URI scheme. The primary ramification is that any bit of data can refer to any other bit of data regardless of its physical location and underlying storage system and format. For instance, a line of text in a .txt file on a hard drive can reference some specific tag in an HTML page on the web. Atop the space-based URI graph, there exists a URI-aware machine capable of processing that data in a storage-agnostic manner.

    data sources are logically abstracted as spaces, where each datum has a uri address enabling the stitching together of database, file system, event, and peripheral data

    A space is a storage and/or processing system that is responsible for maintaining some subset of the full URI address space. Spaces include but are not limited to, relational databases, graph databases, key/value stores, document stores, file systems, large language model catalogs, and more. Spaces can range from the small (a microprocessor's on-board memory), to the large (the world wide web).

    the typical functional programming monad/monoid is extended with a "ringad"/ringoid processor, where * is function composition and + is function branching

    Ring theory describes the underlying algebra of metatron. The virtual machine's instructions can be serially composed (*) and parallelly branched (+) to form program structures that are subject to the axioms and theorems of stream ring theory (a Turing Complete stream computing algebra). Ring theorems realize execution optimization strategies (bulking coefficients), program compiler rewrites (ring equalities), and evaluation semantics (parallel, reducing, and serial execution stages).

    Processes are realized as the propagation of atomic monads maintaining a pointer to their current location in the instruction graph (program counter) and their current location in the data graph (reference in space)

    Monads provide a logical abstraction that cleanly separates the evaluation of a program from the program itself, allowing swarms of monads to operate in parallel over the same instruction/data graphs, where their collective synchronization need only occur when certain "barrier instructions" are reached. The theory of monads is applicable across many areas of applied computing, such as execution stacks, exception handling, I/O management, reflection, program traces, and state history, to name but a few.

    metatron instruction sets (or instset) are packages that encode a domain of discourse within a set of types, instructions, constants, rewrites, and sugars.

    instsets are spaces that can be read from and written to. As a space, they support query processors, with the docq query processor being of particular importance in that it associates documentation with any obj. These objs enable the automatic generation of human-readable HTML documentation as well as agent-readable tool and skill specifications.

    A data structure can have an inter- or intra-space embedding such that each subset of its form can take advantage of the respective time-space tradeoffs of the underlying storage system.

    A data structure such as a vertex in a graph can have many incoming and outgoing edges with different edge labels and properties. Such diversity entails not all edges will require the same read/write performance characteristics. In metatron, it's possible to embed one edge set in a space optimized for fast retrievals (e.g. an in-memory space) and another subset in a space optimized for static, long-term storage (e.g. a disk-backed space). Other considerations may include the indices associated with a space and whether certain properties of an edge can be indexed for non-linear access.

    objs are constrained using a structural type system that can express inherited, refined, dependent, and recursive types with constructs for expressing cardinality, optionals, generics, predicates, and more.

    The structural type system of metatron ensures that the label ascribed to an obj's form (its nominal type) is but a secondary concern relative to the obj's relational structural within the larger data space as a whole. If an obj meets all the specified constraints of a defined type, then it is of that type and can be processed by instructions and composed within larger types requiring said type. From this vantage point, many homomorphic transformations can be realized that render the distinctions between a row in a relational database, a tag in an HTML document, a vertex in graph, and a value in a key/value store to be simply differences of name, not function.

    a monad iterator machine supports speedy traversals over localized regions of space

    OLTP (online transactional processing) provides a straightforward means for accessing a small region of space with a machine that iterates a stream of monads through code from the first instruction to the last.

    a monad swarm machine supports asynchronous, parallel, distributed traversals over large regions of space

    OLRP (online real-time processing) realizes computing as a swarm of asynchronous, distributed monads traversing a data graph whose paths through that graph are guided by an instruction graph. Hundreds of thousands of monads can traverse vast swathes of the data landscape, across different physical machines, all in pursuit of a solution to a problem that has been formally captured within the structure of an obj called code.

    a monad vector machine supports stateful bulk synchronous processing of massive regions of space

    OLAP (online analytical processing) operations are handled by a machine that frames computing as a bulk synchronous process where a series of parallelly executing stages are demarcated by serializing stateful barriers. Together, the pulse of expanding and contracting processes forms the heartbeat of the computation.

    a multi-protocol web-oriented instset expose space resources to external clients as well as realize the external web as a metatron space in and of itself.

    HTTP space translates the GET/PUT semantics of http:// to the read/write semantics of a metatron space -- enabling the selective access, referencing, and manipulation of HTML, XML, and JSON documents. Similarly, WebSocket space offers session-based interactions via a simple string-based mtron evaluation protocol, or an MCP server, or a custom protocol if needed.

    a micropython implementation provides space-aware iot processors that can naturally provide and access data within the larger data space

    a micropython version of metatron enables the numerous ESP32, RapberryPI, etc. processors to maintain a section of the uri address space. These processors' memory and peripherials are accessible to any other metatron device and vice versa. Finally, a MQTT space makes integrating an IoT cluster into metatron a straightforward exercise.

    large language models and their enriching extensions are objs, where self-reflection, introspection, knowledge access, and simulation are natural consequences of metatron's unified address space.

    LLMs are encoded within, operate within, and are knowledgeable about metatron spaces. LLM memory can be persisted or transient. LLM tools can be any mtron instruction, where MCP servers are represented as instructions. LLM skills can be files, web links, or composed of multiple objs across different spaces as long as the result is a markdown obj. Finally, LLM querying is an instruction that can be evaluated by humans and agents alike and/or composed into larger instruction graphs known as workflows.

    A terminal repl and web-based console offer a natural way to move through and manipulate the metatron.

    The console offers a suite of useful features including syntax highlighting, "step-through" compilation, domain/range type checking, auto-complete, AI pair programming via split screen collaborations, and a pluggable framework for custom extensions.
