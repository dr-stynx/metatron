MQTT Pattern Matching Flow
===========================

Example: Read pattern "/sensor/+/temperature"

1. Application calls:
   space.read(f("/sensor/+/temperature"))

2. tbleSpace.directReader() receives pattern:
   pattern = "/sensor/+/temperature"

3. MqttIndexedSchema.read() decomposes pattern:
   segments = ["sensor", "+", "temperature"]

4. Builds SQL query using indexed segments:
   SELECT * FROM objs
   WHERE seg1 = 'sensor'      -- exact match
     AND seg3 = 'temperature' -- exact match
     AND seg4 IS NULL;        -- no extra segments

5. Database uses composite index:
   idx_seg1_seg2_seg3 → Fast lookup!

6. Results returned:
   /sensor/kitchen/temperature  → {"value": 22.5}
   /sensor/bedroom/temperature  → {"value": 20.1}

7. MqttIndexedSchema.matchesMqttPattern() validates:
   ✓ /sensor/kitchen/temperature matches /sensor/+/temperature
   ✓ /sensor/bedroom/temperature matches /sensor/+/temperature

8. JSON deserialized to Obj and returned to application

Path Segment Decomposition
===========================

fURI: /sensor/kitchen/temperature/raw/celsius

Decomposed into virtual columns:
┌──────┬─────────┬─────────────┬─────┬─────────┐
│ seg1 │  seg2   │    seg3     │ seg4│  seg5   │
├──────┼─────────┼─────────────┼─────┼─────────┤
│sensor│ kitchen │ temperature │ raw │ celsius │
└──────┴─────────┴─────────────┴─────┴─────────┘

Pattern: /sensor/+/temperature/#

Matches because:
  seg1 = 'sensor'      ✓ (exact match)
  seg2 = anything      ✓ (+ wildcard)
  seg3 = 'temperature' ✓ (exact match)
  seg4+ = anything     ✓ (# wildcard)

MQTT Wildcard Semantics
========================

Single-level wildcard (+):
  Pattern: /sensor/+/temperature
  Matches: /sensor/kitchen/temperature
           /sensor/bedroom/temperature
  Doesn't: /sensor/kitchen/temperature/raw (too many segments)
           /actuator/kitchen/temperature (wrong first segment)

Multi-level wildcard (#):
  Pattern: /sensor/#
  Matches: /sensor/kitchen
           /sensor/kitchen/temperature
           /sensor/bedroom/temperature/raw/celsius
  Doesn't: /actuator/kitchen (wrong first segment)

Combined wildcards:
  Pattern: /sensor/+/temperature/#
  Matches: /sensor/kitchen/temperature
           /sensor/kitchen/temperature/raw
           /sensor/bedroom/temperature/celsius/current
  Doesn't: /sensor/kitchen/humidity (wrong third segment)
           /sensor/temperature (missing second segment)

Performance Characteristics
============================

Query Type              | Time  | Index Used
------------------------|-------|---------------------------
Exact match             | ~1ms  | PRIMARY (furi)
Single wildcard         | ~5ms  | idx_seg1_seg2_seg3
Multi-level wildcard    | ~10ms | idx_seg1
Complex pattern         | ~15ms | idx_seg2
Pattern > 5 segments    | ~50ms | Full scan + Java filter

Index Selection Examples:

/sensor/+/temperature
  → Uses: idx_seg1_seg2_seg3 (composite)
  → WHERE seg1='sensor' AND seg3='temperature'

/sensor/#
  → Uses: idx_seg1 (single column)
  → WHERE seg1='sensor'

/+/kitchen/+
  → Uses: idx_seg2 (single column)
  → WHERE seg2='kitchen'
